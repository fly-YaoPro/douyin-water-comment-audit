## 用户指定工作簿 / Sheet

当调用消息或同一参数追问线程明确附带飞书工作簿链接/分享卡片，并点名某个 Sheet 时，显式来源覆盖上述固定源表：

1. 用 `+workbook-info` 核对工作簿与 Sheet，优先采用真实 Sheet ID；用户写出的 Sheet 名与 URL 的 `sheet=` 不一致时，以精确 Sheet 名匹配结果为准，并在确认文案中展示最终来源。
2. 导出该 Sheet 的完整 CSV 和整簿 XLSX。先读真实表头，按语义识别机构、发布日期、达人昵称、视频/发布链接、GID；禁止复用固定 H/K/L/M/AR 列号。
3. 日期兼容 ISO 日期、`M月D日`、`M.D`；日期范围提供年份时用该年份归一。空白、普通文字（例如误填“办公任务”）和跨年歧义为无效日期，不得自动臆测。
4. 必须扫描整张 Sheet 的完整 used range，再按用户日期范围过滤；中间空行不会终止读取。
5. 确认文案报告“工作簿 / Sheet / 待扫条数 / 预计耗时”，不再显示默认工作任务与创作线拆分。
6. 首轮固化工作簿 URL、Sheet ID、Sheet 名和清单；24 小时、48 小时与人工复查都重读同一原始 Sheet，并与首轮清单取并集。

## 水评规则

复用 `E:\豆尼·银手\MediaCrawler\tools\water_comment_detector.py`。该检测器覆盖：

- 纯表情、表情密集、贴纸或图片占位；
- 重复夸赞、短泛夸、打卡占位；
- 点赞评论转发等互动任务；
- 引流、招代理、联系方式、购买暗示；
- 功能词 + 空泛宣传词的模板化夸赞；
- 多账号完全相同评论；
- 同一账号 3 条相同或近似评论。

视频升级为问题视频的门槛：

- 候选水评数 `>= 3`；或
- 同一账号相同/近似评论 `>= 3`。

水评举例只展示评论原文，最多 5 条，以 `｜` 分隔；客户表不展示内部英文规则标签。

## 抓取与耗时基准

- MediaCrawler：`E:\豆尼·银手\MediaCrawler`
- 平台：`dy`
- 登录类型：`qrcode`，但复用已保存的隔离浏览器登录态；只有失效才扫码。
- 模式：`detail`
- 每视频最多公开评论：100
- 子评论：关闭
- 当前生产并发：1（历史 2026-08-13 估时基准为并发 3；因接口风控已降并发）
- 批大小：20
- 无头模式：开启
- 输出：JSONL，每批独立目录

2026-08-13 实测：1,207 条视频，共 61 批，用时 4,834 秒（80 分 34 秒），约 4.005 秒/视频。估算公式：

`预计秒数 = max(120, 待扫视频数 × 4834 / 1207)`

对用户显示四舍五入后的分钟，并提示受评论量、短链解析、平台限流影响，可能上下浮动 20%。

### 登录与证据门禁

- 隔离浏览器身份必须同时具备 `HasUserLogin=1` 和 `sessionid/sessionid_ss`；`LOGIN_STATUS` 不是必有 Cookie，不得单独据此打回登录。会话是否真正可用，以首条作品详情接口及证据覆盖率为准。
- 无头任务发现登录失效直接返回 `DOUYIN_LOGIN_REQUIRED`，不在后台等待扫码。
- 抖音 API 返回空正文或 `blocked` 时统一记为 `DOUYIN_ACCESS_REJECTED`。这表示专用会话或抓取通道被拒绝，不能表述为用户抖音账号本体被封禁。
- 单批 0 条详情且出现访问拒绝时立即熔断。整单成功证据覆盖率低于 80% 时，不创建飞书结果表、不发送“0 条异常”结论、不安排自动复查。
- 重新登录后按 1 条、5 条、全量三级恢复；任一级失败都停在当前级别。

## 飞书输出与消息

表格标题：`水评清理-YYYY-MM-DD`；同日重复创建时追加 `-HHmm`。

首轮只创建一个 Sheet：`问题视频`，列顺序固定：

1. 发布日期
2. 达人昵称
3. 发布链接
4. 机构
5. 专项
6. 水评举例

消息由 bot `豆尼·银手` 直接回复原调用内部群或审批群，并原生艾特原发起人询问是否按机构分发。首轮、24 小时和 48 小时各自独立确认；只有原发起人直接回复对应结果消息确认后，才实时重读在线结果，按照 [institution-dispatch.md](institution-dispatch.md) 发送固定机构群；除此之外不得发送客户群或供应商群。

摘要模板：

```text
水评清理结果

表格：<标题>
<链接>

本次共分析达人视频：<清单去重数> 条
成功读取评论区视频：<数量> 条
评论区抽检：<有效且去重评论数> 条
异常数据行：<数量> 条
用时：<时分秒>

问题视频：<数量> 条
水评达人数量（按机构去重）：
- <机构>：<人数> 人

判定规则：候选水评达到 3 条，或同一人重复 3 条，即判定为问题视频。
```

评论统计口径：脚本返回的 `valid_unique_comments` 已经排除了异常 JSONL 行，禁止再次减去 `malformed_jsonl_rows`。

## 24/48 小时复查口径

- 复查对象：按首轮相同发布日期范围重新导出首轮实际数据源（默认任务为工作任务线、创作线两张客户发布表；自定义任务为同一工作簿同一 Sheet），再与首轮固化 `manifest.csv` 按 `aweme_id` 取并集。本轮源表数据优先，首轮独有记录继续保留。不得从首轮结论 Sheet 反推复查对象。
- 对比主键：`aweme_id`；短链只用于展示，不作为跨轮唯一键。
- `可比较视频`：复查输出中存在视频详情或评论读取证据的首轮问题视频。
- `已清理`：首轮命中、复查可比较、复查不再命中。
- `仍有问题`：首轮和复查均命中。
- `无法复查`：首轮命中，但复查没有视频详情或评论读取证据。
- `新增异常`：首轮未命中但复查命中，或在相同发布日期范围内于 24 小时内补登记、且本轮命中的视频；单独列示，不混入首轮清理率分母，也不表述为“新增发布”。
- `处理率 = 已清理 / 可比较视频`；可比较视频为 0 时显示“无法计算”。
- 飞书工作簿在两轮分别追加`24h复查对比`和`48h复查对比`Sheet，并回读核对表头和实际数据行数。H 列“复查结果”后固定为 I 列“人工复查”，整列使用`没水评/有水评`单选下拉，颜色分别为`#bacefd/#fed4a4`。
- 复查 Sheet 生成 2 小时后自动回读。仅将视频明细中人工复查为`没水评`的行写入本地长期排除库，复合主键为规范化后的`发布链接＋达人昵称`。后续检测只有两个字段同时命中才排除；同名不同链接、同链接不同昵称都不得误排。
- 人工复查记忆必须在生成 manifest 后、估时和评论抓取前应用，使被确认的非水评视频不再消耗抓取量，也不进入任何问题统计。
- 所有机构同级展示，不划分试点/非试点；结论以总体数字和机构明细为主，不做无样本支撑的长期效率排名。
- 24/48 小时复查的自动发送目标仍仅限原内部调用群或审批群；不会自动向机构群发送。两轮都在结果中艾特原发起人，只有原发起人确认后才实时读取本轮剩余问题并分机构发送。24 小时卡片警告 48 小时未清完不结算；48 小时卡片告知仍有问题的对应任务不结算。

## 人工复查与长期台账

- 人工复查入口：内部同事引用豆尼已登记的水评结论，并发送明确短指令“复查”或“再复查一下”。豆尼先展示规划，只有同一发起人确认后执行。
- 每次人工复查都在原工作簿末尾新增唯一 Sheet；不覆盖 `问题视频`、`24h复查对比` 或其他历史复查 Sheet。
- 首轮、24 小时复查、48 小时复查和人工复查的结果均追加到长期飞书文档《水评检测与复查台账｜机构执行效率》。每条记录包含可点击结果表、统计、机构明细、结论和不可变记录 ID。
- 台账写入失败进入持久化重试队列，每 15 分钟补写；相同记录 ID 不得重复追加。
